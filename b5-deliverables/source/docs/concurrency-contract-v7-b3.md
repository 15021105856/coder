# v7 B3 并发与版本保护契约

产品仍为 v7 / 7.0.0；本契约涉及浏览器存储协议，不改变训练数据版本。

## 权威数据与兼容

- 新权威键：`physio-log.app-state.v3`，快照格式 3；仍消费格式 2。
- `physio-log.app-state.v2` 只作首次迁移来源，不修改或删除；旧四组件 legacy 键也保留。
- 一旦新键存在，只读新键。旧 HTML 在旧键上的后续编辑不会自动带入新版本；如需保留，先在旧页面导出 JSON，再在新页面明确导入。
- 旧缓存未读到、损坏或不支持格式时，沿用 B1 隔离和救援规则，避免不完整覆盖。

## 提交规则

- 初始化迁移、重载和所有业务保存共用 origin 范围的独占 Web Lock `physio-log.authority-write`。
- 锁内读取最新快照、检查版本、比较载入基底/本页改动/最新数据、合并、写入并回读。
- 不同日期的记录可合并。同日不同内容、删除对编辑、相同数组的不同修改、不同基线修改均为冲突；完全相同的提交可接受。
- daily 的不同对象字段可以递归合并；session/weight 数组整体比较，不在本批猜测项目身份。
- 冲突时不写磁盘，保留本页草稿，可导出 JSON。记录表单显示重载按钮；重载前明确确认放弃本页全部未保存内容。
- 锁缺失、请求失败或 5 秒内无法获得锁时不保存；可浏览和导出。无自行模拟锁或无锁覆盖的降级路径。
- 本页保存未结束时拒绝其他业务修改；提交中的记录表单暂时不可操作，避免草稿与保存基底错配。
- 写后读取异常或不一致只报告结果未知；不再回写旧快照。保存成功后才清除待保存状态和意图。

## 元数据

保存保留已有快照及 daily 信封的扩展字段，revision 增加。较旧数据日期拒绝写入；同日已出现过的旧指纹也拒绝回退。运行中的页面遇到指纹变化，先导出草稿并换最新文件。未知的首次同日新指纹按既定新种子策略处理，并记入 seedHistory，不能凭未见过的文件猜测其实际发布时间。

## 本批边界

实测环境为 Linux Chromium 153、Playwright 1.62.1、`file://`、Asia/Shanghai。浏览器是否共享本地文件存储及 Web Locks 必须在目标环境验证；锁不可用时已实现拒绝保存。独立浏览器配置、隐私窗口、不同 origin 不共享本机数据。本批不实现跨设备同步、数组稳定 ID、完整备份恢复，也不宣布 Windows/手机/Safari/Firefox 放行。

初始权威读取失败时，B1 的显式恢复意图仍在恢复读取后应用；无法重建未读到的载入基底，不能把这类恢复声明成已检测一切历史并发冲突。普通可读基底的并发保护和旧 HTML 权威键隔离已在成品测试中验证。
