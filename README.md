# 北大 346 体育管理学 · 主动提取

这是一个离线网页。它用来练「只看题目，能不能把答案骨架写出来」，并记下用了哪一层提示。它不是电子书，也不是点一下会/不会的闪卡。

资料来自工作区里的两份 Markdown：

- `sources/管理学A册_完整转换.md`
- `sources/管理学B册_完整转换.md`

程序在构建时把教材打进 `dist/index.html`。打开页面时不再读取这两个文件。

## 1. 怎么打开

构建已经生成 `dist/index.html`。用 Windows 的 Edge 或 Chrome **双击这个文件**即可。不需要安装 Node，不需要命令行，也不需要联网。

开发时：

```bash
npm install
npm test
npm run build
```

## 2. 怎么开始「一日记忆恢复」

打开后在「今日训练」点 **排列今日**。安排分成五段：

1. 基线诊断：抽几道 A 题和几道高信号 B 题，全部先无提示。
2. A 册核心题：按章节走。失败时只用已经确认的 B 册骨架。
3. B 级补齐：先看来源标注高的，再看普通骨架。第九、十章不会因为全文更长而排到最前。
4. 红线快测：辨「别写 / 要写」。
5. 晚间闭卷验收：默认留着。白天时间不够时，先减普通 B 项，不取消晚测。

「开始这一段」会进入主动提取。晚测在你按下按钮时，从当天做过的题里抽，并混入少量没做的题。

## 3. A 册和 B 册各是什么

- A 册是考场输出。核心清单是正文里的 26 道完整题，另有附录 2 道真题完整答案。朱红是名解，墨黑是简答，青绿是扩展。
- B 册是骨架、红线和多教材口径。多数题的标准是「能列小标题，每点一句」。第九、十章给了全文，但按骨架背，全文只供查阅，不因此变成更高优先级。
- 没有确认过的 A/B 关系，不会在正式训练里当成「这道 A 题的 B 提示」。

A 册封面写「全 26 题」。B 册目录页写「A级（25道）」。两句都原样留着，程序用的核心题以 A 册正文解析到的 26 题为准。

## 4. 证据状态和主观信心

每一轮的等级由过程算出来，不能手改成「独立提取」：

| 显示 | 含义 |
| --- | --- |
| A·独立提取 | 全程没要提示，主体核对通过 |
| B·基本提取 | 没要提示，主体在，但有少量遗漏 |
| C·提示依赖 | 用了小标题或已审核关键词才恢复 |
| D·看答案后恢复 | 打开了完整原文才恢复 |

主观信心是另外的 1–5 分，只表示你自己的感觉。

## 5. 为什么看完答案后的复述不算首次独立

揭晓前的草稿会冻结在这一轮记录里。撤掉提示后再写一遍，只说明「刚看完还能重现」。它改不了「最高用过哪一层提示」，也改不了本轮证据。

## 6. 怎么备份 JSON

到「设置数据」，点 **导出 JSON**。文件里有 schemaVersion、contentVersion、两册 hash、学习记录、批注、书签、关系审核、关键词审核和设置。

如果浏览器禁止本地存储，页面会提示。这时更要先导出。

## 7. 怎么导入和回滚

1. 选择 JSON。程序只解析和校验，不写入。
2. 看摘要：新增多少、覆盖多少、多少 itemId 对不上、是不是跨资料版本。
3. 点确认后，才先把当前记录存成备份，再写入。
4. 坏文件、缺字段、schema 比程序新，都不会改当前记录。
5. **恢复到导入前备份** 可以回到这次导入之前。

## 8. 怎么更新两份 Markdown

1. 替换 `sources/` 里的两个文件，不要改题干用词。
2. 如果这是一次新的资料版本，把 `scripts/parse-content.mjs` 里的 `CONTENT_VERSION` 改成新的日期版本。
3. 运行 `npm run parse`，再 `npm run build`。
4. 已经人工改过的关系或关键词：在 `manual-review/relations.json` 和 `manual-review/keyword-hints.json` 里把对应条目的 `humanTouched` 设为 `true`。重新解析会保留这些 status。

稳定 itemId 来自来源、类型、章节和题干，不用数组下标。

## 9. contentVersion 和 source hash 变了意味着什么

hash 是两份 Markdown 的 sha256。内容版本或 hash 和本地记录不一致时，程序会按 itemId 接上对得上的记录，对不上的放进「迁移待查」，不静默当成同一道题，也不删掉。

## 10. 怎么确认 A/B 关系

自动结果在 `manual-review/relations.json`，也在「设置数据」里。

- `confirmed-by-source`：同章，且红线「别写」或骨架标题里有题干中的连续原文（至少 4 个字，泛词除外）。理由写在 `reason`。
- `candidate`：同章邻近原文、或「见第 X 章第 Y 题」这类编号。编号不一定就是 A 册题序，所以不自动进提示链。
- 在页面上点「确认」后，这条关系才会在正式训练里作为 B 册骨架或相关红线出现。点「不用」会排除，即使原来是源文确认。

这些选择存在学习记录里，不写回教材原文。

## 11. 怎么确认关键词

`manual-review/keyword-hints.json` 里的短语都是源文引号中的原词，初始都是候选。

没有已确认关键词的题，提示链会从小标题直接进入完整原文，中间不生成新词。

在设置里搜索后点「确认」，或在文件里把 `status` 改成 `confirmed` 且 `humanTouched` 设为 `true` 后再解析。自定义关键词必须是该题原文里真实存在的连续片段，否则页面会拒绝。

## 12. Windows Edge 三分钟验收

当前开发环境不是 Windows。**Windows Edge 尚未实机验证。** 请在自己的电脑上做这几步：

1. 双击 `dist/index.html`。
2. 打开资料库，找一道 A 题，例如目标管理。
3. 进入主动提取：写草稿，要一次提示，对照原文，撤提示后再写，记下这一轮。
4. 刷新页面，到学习档案看草稿还在。
5. 导出 JSON。
6. 关掉浏览器再打开同一个文件，记录仍在。
7. 再导入刚才的 JSON，看摘要后确认；如需恢复，点回滚。

请同时看地址栏是不是 `file://`，以及开发者工具的网络面板没有对外请求。

## 13. 已知限制

- 没有后台推送。到期只在你打开页面时看得到。
- 间隔是写明的分钟/小时/天规则，不是医学遗忘曲线。
- 不按字符相似度给简答打分，也不显示「掌握率」或预测命中率。
- 第九、十章全文默认折叠。优先级看来源标注、是否到期、最近是否要提示，不看篇幅。
- 大部分 A/B 骨架关系仍是候选。没确认之前，A 题失败后用的是这道题自己的源文小标题。
- 关键词在你确认之前全部跳过。
- B 册「见第一章第三题」和 A 册题序对不齐，只留在候选里。
- 合用红线留在资料原来的那一章，不复制到另一章。
- 批注、确认、自定义关键词都在浏览器本地，不改 Markdown。
- 单文件很大，因为教材已打进页面。
